Helix Heal

Run it after a failed Playwright job. Helix reads the report and trace, finds broken locators, validates replacements, and returns a reviewable patch.

The after-failure loop

From red CI to reviewed locator patch

1

Parse the failed run

Helix reads Playwright JSON reports, failed test metadata, retries, traces, and source paths.

2

Inspect trace evidence

Trace DOM snapshots and accessibility nodes become candidate locators with confidence signals.

3

Validate before patching

Static and optional live validation check that the locator resolves uniquely and is actionable.

4

Return a reviewable diff

AST-safe patching changes only the matched locator and explains ambiguous or unsupported cases.

CLI

Install, analyze, patch

The CLI is designed for local diagnosis and for CI artifacts. It writes Markdown reports, dry-run patches, cache entries, and a static dashboard. 

npx helix-heal analyze \
  --report playwright-report.json \
  --trace test-results \
  --source-root .

npx helix-heal patch --dry-run \
  --report playwright-report.json \
  --trace test-results \
  --source-root .

GitHub Action

Run Helix after Playwright fails

- name: Run Playwright
  id: playwright
  run: npx playwright test --reporter=json
  continue-on-error: true

- uses: martjustin/helix-heal@main
  if: steps.playwright.outcome == 'failure'
  with:
    playwright-report: playwright-report.json
    trace: test-results
    source-root: .

Output

Concrete suggestions, not vague failure summaries

A Helix run can produce a PR comment, Markdown report, dry-run patch, and static team dashboard artifact. The current MVP stays intentionally narrow: repair locators first.
